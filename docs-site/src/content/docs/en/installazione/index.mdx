**Porto** is the free, source-available management system for marinas, tourist ports, berthing points and
boatyards. It is developed by [Coste360 SRL](https://www.coste360.it/).

It covers the whole marina cycle: a to-scale harbour map (quays, piers, fingers, buoy fields, dynamic areas, yards,
sheds, parking and boxes), customers and vessels, price lists, mooring contracts and transits, berth rights and
condominium charges, charges and payments, dry storage, boatyard, rentals, online berth booking, occupancy sensors,
the public marina profile and reports.

## How it is built

- **One Go binary** (`porto`) with the REST API, the admin panel, the public booking page and the marina profile.
  No mandatory external service: no Redis, queues or object storage.
- **Database**: SQLite built in (one file in the data folder) or optional PostgreSQL, with the same schema.
- **Desktop app** for Windows, macOS and Linux: runs the same server on the office PC and works without internet.
- **Interface** in Italian and English, light and dark theme, usable from a phone (PWA).
- **No artificial intelligence and no telemetry**
  ([ADR 0008](https://github.com/coste360/porto/blob/main/docs/adr/0008-nessuna-intelligenza-artificiale.md)): the
  marina's data stays on the computer or server you choose.

## What Porto does not do

- **It does not issue invoices** and sends nothing to the Italian e-invoicing exchange (SdI): it exports charges "to
  invoice" for the marina's invoicing software ([Charges and payments](/en/gestore/addebiti-e-incassi/)).
- **It is not a fiscal cash register**: receipts printed by Porto are courtesy receipts, not fiscal documents
  ([Cash register and daily takings](/en/gestore/cassa-e-corrispettivi/)).
- It ships no drivers for specific invoicing software, advanced signature providers, third-party booking portals or
  real fiscal printer models: these are extension points ([Extensions](/en/sviluppo/estensioni/)).
- Tax compliance of the configuration (VAT rates, issuing documents, retention) remains the responsibility of the
  marina and its accountant.

## Where to get it

The source code is on [GitHub](https://github.com/coste360/porto); ready-made binaries are not attached to GitHub
releases. The Docker image `ghcr.io/coste360/porto` (amd64 and arm64) is public and published with every release. The desktop packages are downloaded from
[portomarina.app/download](https://portomarina.app/download/). Nothing needs to be installed on phones: the panel
opens in the browser and can be added to the home screen as an app (PWA). See
[Choose how to install](/en/installazione/scegli-come-installare/).

:::caution[Project status]
All milestones of the specification (M0 to M12) are implemented and covered by automated tests; version 1.0.0 is
the first public release. Porto is provided as is, without warranty: for a supported installation contact
[Coste360](https://www.coste360.it/contatti).
:::

## Known limits

- The desktop packages build from source, but signing and notarisation need Coste360's certificates: the signed
  packages are the ones on [portomarina.app/download](https://portomarina.app/download/).
- No drivers are included for specific invoicing software, advanced signature providers, third-party booking channels
  or real fiscal printer models: they are [interfaces](/en/sviluppo/estensioni/).
- The boatyard warehouse is limited to the materials booked on work orders.
- Rentals cannot be sold from the public page yet.
- There is no reference hardware partner for sensors yet.
- Double berthing (a boat moored alongside another) is not handled.

## Roadmap

After the first version: InfoCert signature, exporters for the most common invoicing software, a hardware partner for
sensors, online sale of rentals and the boatyard warehouse. Under evaluation: mandatory reporting, foreign markets,
double berthing and an app for boaters; the
[open decisions](https://github.com/coste360/porto/blob/main/docs/spec/33-decisioni-aperte.md) are not taken in code.
A native mobile app for staff is not part of this repository.

## Accessibility

Porto targets **WCAG 2.1 level AA** (European standard EN 301 549) on the public booking page, the widget and the
customer area, and applies the same checks to the main pages of the admin panel.

- **A map that works without sight**: every berth is a button with a full name (code, status, boat) and the **List**
  button shows the same data as a list.
- **Colour is not the only cue**: every map status also has a glyph, explained in the legend.
- **Contrast** of the light theme, the dark theme and the map lenses is checked by automated tests.
- **Two languages**, Italian and English, for the panel, the public page and emails.

The end-to-end tests run axe-core with the WCAG 2.0 and 2.1 level A and AA rules, in light and dark theme, on the
booking page, the customer area, login, the dashboard, reports and the main panel pages: a serious or critical
violation fails the tests.

Since 28 June 2025 the European Accessibility Act (EU Directive 2019/882, in Italy Legislative Decree 82/2022)
requires online booking services for consumers to be accessible and the provider to state it; micro-enterprises are
exempt. Porto provides the tool, but the service remains the marina's responsibility.

Limits: the payment page belongs to the provider (Stripe); texts, photos and the site hosting the widget depend on the
marina; the map editor is designed for mouse or touch; no audit with users of assistive technologies has been done
yet.

Questions about the licence, offline use or invoicing? See the [FAQ](/en/installazione/domande-frequenti/).
